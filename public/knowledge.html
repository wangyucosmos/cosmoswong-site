词它是什么解决什么问题

六、ChatGPT 为什么特殊

ChatGPT 没有文件系统，既读不到你的本地文件夹，也读不到私有仓库。所以它是唯一不能直接看那份实体的工具，只能通过两条虚线通道：

其他四个工具没有这个问题：它们读的是同一个文件夹，卓望和求职天然在一起。

两个仓库各管哪一半

~/Documents/我的知识库/                    ← 本地实体（全部）
├── 知识库规则.md、INDEX.md              ┐
├── 求职相关/                            ├── push → my-knowledge-base（私有）
├── 个人学习ai 相关/                     │
├── Claude 搭建措施相关/                 ┘
└── 卓望工作相关/卓望/                   ─── push → zhuowang-workspace（公开）
  • zhuowang-workspace ≠ my-knowledge-base，内容不重叠：前者只有卓望那个子目录，后者是除卓望之外的所有东西。
  • zhuowang-workspace = 本地 卓望工作相关/卓望/，只要收工时 push 了，两边就一样。所以 ChatGPT「卓望」Project 拉直链拿到的就是最新的卓望内容——这一块已经是同步的。
  • 会落后的只有另一半：求职、DSH、Claude 搭建这些在 my-knowledge-base，它是私有的，ChatGPT 读不到直链，只能靠手动上传快照。

想让 ChatGPT 这一半也自动同步，有三条路

方案做法代价
A. ChatGPT 的 GitHub 连接器ChatGPT 设置 → Connectors → 连接 GitHub 账号 → 授权它读 my-knowledge-base最干净，私有仓库也能读。但要看套餐/地区有没有这个功能，得去设置里看一眼
B. 再建一个公开的「精简仓库」加个脚本，收工时把 知识库规则.md、INDEX.md、DSH 手册这类不含个人信息的文件自动复制推到一个公开仓库，ChatGPT 走直链多一个仓库要维护；简历这类永远进不去
C. 保持现状快照手动传，AI 收工时提醒重传零成本，就是偶尔要拖一次文件

建议先试 A：去 ChatGPT 设置里找「Connectors / 连接器」，看列表里有没有 GitHub。有 → 连上，把「我的知识库」Project 的指令改成读仓库；没有 → 看求职/DSH 这些在 ChatGPT 里用得多不多，多就上 B，不多就 C。

七、常见疑问

以后开工还要读 GitHub 吗？
不用。本地那份就是最新的，谁改了都在同一个文件夹里。开工时的 git pull 只是安全检查，99% 的时候什么都不做。
那 GitHub 到底干什么用？
三件事：电脑坏了能取回；改错了能回退到任何一次提交；ChatGPT 靠公开那个仓库的直链读卓望。
本地只有一份，误删了怎么办？
从 GitHub git clone 回来就是。前提是收工时有 push——这就是为什么「收工必 push」这条规矩要守住。
什么该进知识库，什么不该？
进：你确认过的规则和偏好、项目总结、进度、定稿、踩坑经验。不进：草稿、比稿落选版、脚本工具、任何密码密钥。你不用自己判断——每次收工 AI 会列出来问你。
换了电脑怎么办？
两个仓库各 clone 一次，把卓望那个放进外层库的 卓望工作相关/卓望/，再把四个工具的全局指令文件复制过去，就恢复了。
Obsidian 和这套 AI 共享有关系吗？
没有依赖关系。Obsidian 只是你自己看这个文件夹的软件；关掉它、卸载它，AI 照常工作。
