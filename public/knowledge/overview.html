知识库架构说明

一份本地文件夹，两个 GitHub 备份，五个 AI 工具各自怎么进出。记录于 2026-09-15，结构变了以库里的 知识库规则.md 为准。

先记住三个数字：1 · 2 · 5
  1. 1 份实体：所有知识只存在 ~/Documents/我的知识库/ 这一个文件夹里。改，就是改它。
  2. 2 个 GitHub 仓库：只是这个文件夹的云端备份和修改历史，平时不用从它们拉东西。
  3. 5 个 AI 工具：Claude Code、Codex、DeepSeek Harness、Claude Cowork 四个直接读写那份实体；ChatGPT 读不到本地，但通过 GitHub 插件读两个仓库——看到的是最后一次 push 的版本。

一、四个词分别是什么

「知识库」和「GitHub 仓库」有什么不同？它们其实是同一个文件夹的四个侧面：

词它是什么解决什么问题
文件夹硬盘上的 我的知识库/，里面是一堆 .md 文本知识本体。删了它就没了。
Obsidian给你用的浏览器/编辑器，打开那个文件夹你自己翻、搜、看双链图谱。.obsidian/ 里只有它的界面设置，不碰内容。
GitHub 仓库那个文件夹在云端的一份拷贝，附带每次修改的历史电脑坏了不丢；改错了能回退；换电脑能取回。
CLAUDE.md / AGENTS.md给 AI 看的入口说明，放在文件夹根目录AI 打开文件夹时知道先读什么、规矩是什么。

六、ChatGPT 为什么特殊

ChatGPT 没有文件系统，读不到你的本地文件夹。它靠 GitHub 插件读两个仓库（2026-09-15 验证私有仓库也能读），所以它看到的永远是最后一次 push 的版本——本地改了没 push，它就不知道。它是唯一不碰那份实体的工具：

其他四个工具更直接：它们读的是本地那个文件夹，不经过 GitHub。

两个仓库各管哪一半

~/Documents/我的知识库/                    ← 本地实体（全部）
├── 知识库规则.md、INDEX.md              ┐
├── 求职相关/                            ├── push → my-knowledge-base（私有）
├── 个人学习ai 相关/                     │
├── Claude 搭建措施相关/                 ┘
└── 卓望工作相关/卓望/                   ─── push → zhuowang-workspace（公开）
  • zhuowang-workspace ≠ my-knowledge-base，内容不重叠：前者只有卓望那个子目录，后者是除卓望之外的所有东西。
  • zhuowang-workspace = 本地 卓望工作相关/卓望/，只要收工时 push 了，两边就一样。所以 ChatGPT「卓望」Project 拉直链拿到的就是最新的卓望内容——这一块已经是同步的。
  • 求职、DSH、Claude 搭建这些在 my-knowledge-base（私有）。ChatGPT 通过 GitHub 插件读它，同样以上一次 push 为准。

曾经的三条路，最终走了 A

私有仓库 ChatGPT 本来读不到直链，当时摆过三条路：A 用 ChatGPT 的 GitHub 插件读私有仓库；B 另建一个只放非个人信息文件的公开仓库；C 手动上传快照。2026-09-15 验证 A 可行（插件能读出私有仓库里当天刚改的内容），于是 Project 里的快照全部删除，B、C 作废。

七、常见疑问

以后开工还要读 GitHub 吗？
不用。本地那份就是最新的，谁改了都在同一个文件夹里。开工时的 git pull 只是安全检查，99% 的时候什么都不做。
那 GitHub 到底干什么用？
三件事：电脑坏了能取回；改错了能回退到任何一次提交；ChatGPT 靠 GitHub 插件读两个仓库。
本地只有一份，误删了怎么办？
从 GitHub git clone 回来就是。前提是收工时有 push——这就是为什么「收工必 push」这条规矩要守住。
什么该进知识库，什么不该？
进：你确认过的规则和偏好、项目总结、进度、定稿、踩坑经验。不进：草稿、比稿落选版、脚本工具、任何密码密钥。你不用自己判断——每次收工 AI 会列出来问你。
换了电脑怎么办？
两个仓库各 clone 一次，把卓望那个放进外层库的 卓望工作相关/卓望/，再把四个工具的全局指令文件复制过去，就恢复了。
Obsidian 和这套 AI 共享有关系吗？
没有依赖关系。Obsidian 只是你自己看这个文件夹的软件；关掉它、卸载它，AI 照常工作。
