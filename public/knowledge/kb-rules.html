知识库规则（Claude Code / Claude Cowork / Codex / DeepSeek Harness 共同遵守）

本文件是四个 AI 工具共用的契约。任何工具在任何文件夹里开工，只要任务涉及本库的主题，都按这里执行。 本库位置：~/Documents/我的知识库/（同时是 Obsidian 库）。

图片怎么判断（2026-09-21 确认）

分界线只有一条：这张图是用来「解释某条知识」的，还是「待使用的生产资料」。

  • 进：后台操作截图、页面效果示意、原型预览图、被规范条目引用的参考图。 它们脱离所属文档就没有意义，体积小，属于文档的一部分。
  • 不进：切图、banner、设计稿源文件、整套活动图集。 二进制、量大、git 会持续膨胀且删不掉，Obsidian 也搜不了内容，没有版本对比价值。 这类只在文档里写一行路径索引，本体留各自工作区。

存放规范：配图放所属文档同级的 附件/ 子文件夹，文件名用「主题-序号-做什么.png」， 不要留 Obsidian 默认的哈希文件名——两个月后你点开都不知道它是什么，等于白存。

注意 Obsidian 默认行为：未设置附件目录时，粘贴的图片一律落在库根目录且以哈希命名。 建议在 设置 → 文件与链接 → 附件默认位置 改为「当前文件所在文件夹下的子文件夹」，填 附件。

3. 开工协议（每个工具、每次任务）

  1. 读本库 关于我.md：用户是谁、怎么合作、明确说过的工作习惯（2026-09-29 起）。
  2. 读本库 INDEX.md，找到任务对应的主题子文件夹。
  3. 读该主题的 主档（主题名.md）和 进度（进度.md，如有）。
  4. 主题有自己的 流程/（如卓望），按其 INDEX.md 路由到具体流程文件。
  5. 没有对应主题 → 告诉用户「知识库里没有这个主题的记录」，问是否新建子文件夹。
  6. 读完才能开始产出。不得跳过。

用户在对话里说了新的长期偏好（「以后都这样」「记住」），收工沉淀提醒里建议写进 关于我.md，用户确认后写入。

4. 收工协议 —— 必须主动提醒用户（用户自己可能判断不了）

每次任务结束前，工具必须输出一段「知识库沉淀提醒」，格式固定：

📥 知识库沉淀提醒
本次任务产生了以下可能需要共享的内容：
1. [结论/规则] ……  → 建议写入 `主题/主档.md` 的「xx」节
2. [进度]       ……  → 建议更新 `主题/进度.md`
3. [定稿]       ……  → 建议复制到 `主题/交付物/xxx-定稿.html`
4. [经验/坑]    ……  → 建议写入 `主题/主档.md` 的「经验」节
5. [上站]       ……  → 适合放到个人主页 cosmoswong.com 的哪个板块（作品集/工具箱/旅游/健身/收藏）
（没有的项写「无」）
要我现在写入吗？（是 / 只写第 N 项 / 都不写）

判断触发的标准（有一条就要提）：

  • 用户在本次对话里确认或否定了某个做法、偏好、规则
  • 完成了一个阶段性产物（策划案、原型、文档、报告、脚本工具）
  • 推进了某个项目的进度
  • 踩了坑、找到了原因、有可复用的解法
  • 用户说了「以后都这样」「记住」「下次注意」
  • 产出了适合放到个人主页 cosmoswong.com 展示的东西（判断标准见 个人主页/个人主页.md）

用户回复后再写入；写入时修订原条目而非堆叠，与现有规则冲突则保留最新确认结论并注明替代关系。 纯问答、闲聊、没有任何新结论的任务：提醒可以简化为一句「本次无需沉淀」。

5. 并行比稿规则

用户经常让多个工具各做一版来对比。规则：

  • 比稿产物留在各自工作区，文件名带工具后缀（-claude / -codex / -dsh / -cowork）。
  • 比稿阶段任何工具都不写知识库（不动主档、不动进度）。
  • 用户选定后，由被选中的那个工具执行收工协议，把定稿和结论沉淀进去。

6. 子文件夹规范（防乱）

每个主题一个子文件夹，结构统一：

主题名/
├── 主题名.md     ← 主档：稳定知识、规则、偏好、经验（必有）
├── 进度.md       ← 做到哪了、下一步（有进行中的项目才建）
├── 流程/         ← 该主题专属 SOP（需要时才建，入口 INDEX.md）
└── 交付物/       ← 定稿成品（需要时才建）
  • 新建子文件夹后，必须在根 INDEX.md 登记一行（做什么的 + 主档路径）。
  • 文件名用中文可读名，不用 新建文件夹、未命名、(1)。
  • 不得创建 xxx-最新版.md、xxx(1).md 这类平行版本；只有一个主档。
  • 不要把「会变的内容」写进本索引：文件/条目数量、省份名单、当前选中的节点或版本号、日期区间这类东西一定会过期。INDEX 一行只写「这份文件是干什么的 + 权威来源在哪」，具体内容留在文件本体里。
    • 正例：负责省份清单写在 卓望工作相关/卓望/卓望.md「基本信息」那一行；INDEX 只写「见那里」，不复制名单、不写数量。
    • 反例（2026-09-20 已修）：INDEX 里写过「剪藏 6 篇」，当天就变成 7 篇。
    • 通用原则：会变的东西只维护一处，别处一律引用（与第 8 条冲突优先级配合）。

7. Git 与备份

  • 整个 我的知识库/ 是一个 git 仓库（私有 GitHub wangyucosmos/my-knowledge-base），用于备份和历史。
  • 卓望工作相关/卓望/ 有自己的仓库（wangyucosmos/zhuowang-workspace），在外层 .gitignore 里排除；它的提交推送规则见其 AGENTS.md。
  • 收工写入知识库后：git add -A && git commit -m "docs: ..."，能联网的工具再 git push。
  • Claude Cowork 连不上 GitHub：只本地 commit，由 Claude Code / Codex 或用户之后 push。
  • Claude Cowork 连本地 commit 也做不了（2026-09-21 实测）：它没有删除文件的权限， 而 git 每次写操作都要清理自己生成的 .git/index.lock，删不掉就卡死， 且该锁文件会残留、导致后续所有 git 操作失败。申请删除权限会被安全策略拦截。 结论：Cowork 只负责改文件，不要让它跑任何 git 写命令； 它应在收尾时把 rm -f .git/index.lock && git add ... && git commit ... && git push 整条命令交给用户执行。
  • 同一时间只让一个工具改同一个主题的主档/进度（并行比稿见第 5 条）。

8. 冲突优先级

用户当前明确指令 > 本库主档 > 任何工具自己的记忆 / 历史材料 / 其他副本。

11. 状态一致性：谁做完谁回写（跨 AI 看板自愈）

要解决的问题（真实发生过）：某个工具（如 Claude）把一件事做完并交付了，但它没有回写 进度.md；于是另外几个工具（Codex／DSH／ChatGPT）下次开工还看到「进行中」或「断的」，重复劳动、或基于过时前提推进。

规则：

  1. 完成即回写，不要等「收工」：任务一旦完成、交付、或被用户确认，就由实际完成它的那个工具立刻更新对应 进度.md 的那一条（状态／下一步／最近经手／更新日期），然后 commit + push。
  2. 本地 commit ≠ 别人知道：连不上 GitHub 的工具（如 Cowork）必须明确写出「本机已 commit、待 push」，交由 Claude Code / Codex / 用户执行 push。
  3. 只写状态，不写流水账：看板写「现在什么状态 + 下一步可执行动作」；过程、草稿留在各自工作区。
  4. 发现不一致，任何工具都可当场更正：同一份文件前后矛盾时（例：前面写「已选定某方案」，后面还写「待对比选一版」），以时间较新的结论为准；更正时在差异处注明「谁在何时更正」，不必等原作者。
  5. 同一时刻只由一方写入（配合第 5 条并行比稿规则），避免互相覆盖；有未提交改动或冲突时先停下报用户。
  6. 判断标准（与卓望看板一致）：「如果另一个工具明天开工不知道这件事，会不会做错？」会 → 必须回写。

闭环范例（2026-09-20 实跑通过）：ChatGPT 读公开仓库 → 发现 4 处看板与事实不符（旧口径未更新、已完成未回写、已交付未归位、上线状态过期）→ 报给用户 → 用户拍板 → DSH 单独写入并 push → 下一轮 ChatGPT 读到修正版。 职责分工：读的人负责发现，干活的人负责回写，用户负责拍板。

用户可复用的一句话（直接触发回写）：

「这件事已经完成／我已经交付了，请把进展回写到知识库对应的 进度.md，并 push。」

⭐ 最简触发词（用户不用保存、不用背长句）：用户对任何工具说「同步一下」／「回写进度」／「这事做完了」／「我已经交付了」中任意一句，即等于下达「回写」指令 → 立刻执行上文流程（写 进度.md + commit + push），不得只口头答应。

补充：各工具的会话日志在本机可读（方法见 个人学习ai 相关/进度.md），可用来核对「对方到底做到哪了」；但日志只是过程，权威状态仍以 进度.md 为准。

15. 凭据边界规则（2026-10-18 立）

背景：本库会被 4 个 AI 工具读取（Claude Code / Claude Cowork / Codex / DSH）。.gitignore 只挡 git，不挡 AI 读取 —— 这个区别曾被误判成"没入库就安全"。2026-10-18 实际发生过：一份含 DECODO 密码的真值版文件躺在知识库目录里，而 CLAUDE.md 的「主题 → 目录」路由行还明确指向了那个目录（等于每次开工都邀请 AI 去读）。

四条硬规则

  1. 含真实凭据的文件，一律不放在任何 git 仓库内（知识库、工作区仓库都不行）。 统一放仓库外独立目录：~/Documents/claude-isp-secrets/（不随任何仓库，附 README 说明铁律）。
  2. .gitignore ≠ 安全。判断标准是「目录在不在仓库里」，不是「有没有被 git 忽略」。
  3. CLAUDE.md / AGENTS.md 的「主题 → 目录」路由，不得指向含凭据或高度敏感的目录。
  4. 写「脱敏复查 / 安全记录」这类文字时，禁止引用真值做示例 —— 2026-10-18 就发生过：把真用户名写进了"已脱敏"的记录里。示例一律用 <DECODO用户名> 这类占位符。

自检命令（随时可跑，三条都应无输出）

cd ~/Documents/我的知识库
# 关键词故意拆开写：避免本文件自己命中，也避免把凭据原文留在文档里
U="spchj1""ctfv"; P="S27OFa""Mnhkc6gbp"
# ① 工作区文件里有没有凭据
grep -rl "$U\|$P" --include="*.md" --include="*.yaml" --include="*.txt" . 2>/dev/null
# ② git 追踪的文件里有没有（这条才决定会不会上 GitHub）
git grep -l "$U\|$P"
# ③ 历史提交里有没有出现过
git log --oneline -S"$U" --all | head
# ④ 顺带扫别的常见凭据形态（私钥/Token/密码字段）
grep -rlE "BEGIN (RSA|OPENSSH|PRIVATE) KEY|password:\s*['\"]?[A-Za-z0-9!@#%^&*._-]{6,}" \
  --include="*.md" --include="*.yaml" --include="*.txt" . 2>/dev/null | head

注：检查脚本本身也不能包含凭据原文（否则文档自己就成泄漏源，且每次自检都会命中自己）。所以上面用 "spchj1""ctfv" 这种拆写方式。

万一凭据已经进过 git

情况 处理
私有仓库 + 只是用户名片段（无密码） 风险可控，但必须改掉当前文件并记进 进度.md
任何仓库 + 出现过密码/Token 视为已泄露 → 立即更换凭据（改密码，比清历史重要）
公开仓库 立即换凭据 + 用 git filter-repo 清理历史

  1. 按工具区分可见范围：「谁需要知道」要分开。Codex / DSH 要维护这套环境 → 保留路由；Claude 侧最小化 —— 不在 ~/.claude/CLAUDE.md 的主题列表里出现该主题，并在 ~/.claude/settings.json 加权限拒绝（即使被要求也读不到）：

    { "permissions": { "deny": [
    "Read(//Users/<你>/Documents/我的知识库/Claude 搭建措施相关/**)",
    "Read(//Users/<你>/Documents/claude-isp-secrets/**)" ] } }

    改完必须用 python3 -m json.tool ~/.claude/settings.json 校验，JSON 写坏会让 Claude Code 起不来。

  2. 知道 permissions.deny 的边界：它只挡 Read 工具，挡不住 Bash 里的 cat / git show / python3 -c。所以 deny 是「降低概率」，不是「绝对隔离」；要绝对隔离，只能把文件移出该 AI 的可达路径（本例：真值文件放仓库外 ~/Documents/claude-isp-secrets/）。 推论：任何「会被自动注入 / 会被读取」的文件都不能放凭据 —— 首当其冲是 DD.md（长期记忆，每次会话注入）和各工具的 CLAUDE.md / AGENTS.md。2026-10-18 就发生过：DD.md 里藏着 2 处 DECODO 密码。

  3. permissions.deny 的路径写法（踩过坑）：Claude Code 的绝对路径规则必须是 Read(//绝对路径)（双斜杠）；写成 Read(///Users/…)（三斜杠）会被静默忽略、等于没生效（2026-10-25 实际踩过：12 条规则因此全失效）。为兼容不同版本匹配规则，关键目录同时写 //绝对路径 与 ~/家目录路径 两种形式最稳。 改完务必 python3 -m json.tool ~/.claude/settings.json 校验，并逐条核对是否真的覆盖到目标文件（不要只看条数）。

给 AI 看的东西怎么办

  • 一律用公开版（占位符）；真值版只在仓库外、只给人自己看。
  • 需要 AI 帮忙排障时：喂公开版 + 命令输出，不要喂真值文件（AI 读文件 = 内容会发到厂商服务器）。
