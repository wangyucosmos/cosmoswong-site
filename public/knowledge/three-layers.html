知识 / 进度 / 流程：三层分工

为什么流程要放进仓库而不是各工具的本地技能，以及各工具的接入方式

本目录存怎么做（步骤、顺序、验收清单）；卓望.md 存是什么（业务规则、省份线索、样本、规范）。 两者不重复：流程文件只写步骤并引用 卓望.md 的章节名，不复述其中的知识内容。 知识变了只改 卓望.md，流程文件通常不用动。

为什么流程放在仓库里

Claude、Codex／ChatGPT、DeepSeek 三方各有自己的本地技能机制（.claude/skills、~/.codex/skills、.dsh/skills）， 但本地技能一旦写入业务知识就会各自漂移——2026-08-25 已实测到 DeepSeek 本地技能仍写「三个重点省份」「原型默认高保真」， 与当时的 卓望.md 不一致。

因此约定三层分工：

层 放哪 内容 更新方式
知识层 仓库 卓望.md 业务规则、省份线索、样本、规范 收工沉淀，git 提交
流程层 仓库 流程/*.md（本目录） 步骤、顺序、验收清单 发现更优流程时提交
触发层 各工具本地技能目录 只写「何时触发 + 先 pull + 去读哪个流程文件」 极少改动

触发层不得包含任何业务知识。 本地技能里出现省份名单、奖励额度、视觉默认值、版式参数都属于违规， 因为那些一定会过期。

三方接入方式

2026-09-15 起本仓库只有一份实体：~/Documents/我的知识库/卓望工作相关/卓望/。 Claude Code（claude code new/卓望/卓望知识库/zhuowang-workspace）、Codex（CODEX项目/拓维卓望/卓望知识库/zhuowang-workspace）、 DeepSeek Harness（deepseek harness/卓望）三个入口都是软链到它。本地即最新，GitHub 只做备份与历史； 「开工先 pull」保留为安全检查。个人知识库总规则见上一级的 我的知识库/知识库规则.md。

四个入口的能力不同，接法也不同：

  • Claude Code —— 项目 .claude/skills/ 下的薄触发技能，会话内自动触发
  • Codex —— ~/.codex/skills/ 下的薄触发技能
  • DeepSeek Harness —— .dsh/skills/ 下的薄触发技能
  • ChatGPT 网页版／Codex —— 账号侧 Skill（如「卓望活动运营」）只能当触发层。 Skill 本体存在 OpenAI 账号里、不在本仓库，Claude 与 DeepSeek 物理上读不到，也没有版本历史可供验证， 因此任何业务知识和执行步骤都不得写进 Skill 正文，只写「先读仓库」。没有 Skill 机制时， 在项目自定义指令里写同一句话。

四方共同认的是本仓库，不是某个本地技能文件。本地技能只是「把它们赶去读仓库」的开关。
